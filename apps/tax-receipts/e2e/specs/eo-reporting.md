# EO evaluation: Reporting

## Application Overview

Covers EO checklist rows 66-69 on the Entity reports screen (/spaces/:periodId/:entityKind/entity-reports; riding spaces add ?ridingNumber=121). Heading "Entity reports"; subtitle "Period 9503 · Party (province-wide)" or "Period 9503 · Riding 121 · Constituency association". Form: Report select ("ALL (annual contribution roster)" / "S2P2 (over-$200 contributor aggregate)"), textbox "Political entity label (as it should print on the file)" (prefilled "Green Party of Ontario" on party spaces, EMPTY on riding spaces and required there), textbox "Reason for generating (required)", button "Generate" (disabled until a reason, and on riding spaces the label, is filled). The list table has columns Kind, Generated, Rows, Status (Clean / "Dirty — changed since generated"), Sent to CFO ("Mark sent"), and per-row links "Download CSV" (href /api/entity-reports/<id>/csv) and "View changes". All scenarios start signed out and use signIn(page, user) from tests/helpers.ts. Generated reports are append-only: never assert how many reports a space lists; find the row this scenario generated (newest row, first row of tbody, kind cell and a Generated time at or after the click). Use unique reasons (suffix timestamp). Dates in the CSV are MMDDYYYY; receipt numbers (GPO-004025xx) and Receipt_Issuance_Date (the seed day) are run-dependent, so do not assert them. Contributor_ID values (T33...) come from the seed, treat as unstable too. Fixture display names are first name then last name, so Split Sam prints as Contributor_First_Name=Split, Contributor_Last_Name=Sam. Consolidating Chris has no first or last name stored, so it prints whole in Contributor_Last_Name with an empty First_Name. Parse the CSV by header name, not position, for data, and also assert the full header string.

CSV helper for all scenarios: click the "Download CSV" link in the generated row with page.waitForEvent('download'), read with download.createReadStream() (as readAll in helpers.ts), split on newline, split on comma (no quoted fields in this data), and build row objects keyed by the header.

EXACT HEADERS observed live.
ALL (21 columns): Party_ID,Contributor_ID,Receipt_Number,Receipt_Status,Agency_Contribution,General_Meetings,Political_Entity_Type,Political_Entity,Contribution_Amount,Contribution_Type,Acceptance_Date,Receipt_Issuance_Date,Contribution_Period_ID,Contributor_Type,Contributor_Last_Name,Contributor_First_Name,Organization_Name,Contributor_Address,Contributor_City,Contributor_Province,Contributor_Postal_Code
S2P2 (14 columns): Party_ID,Contributor_ID,Political_Entity_Type,Political_Entity,Contribution_Period_ID,Contributor_Type,Contributor_Last_Name,Contributor_First_Name,Organization_Name,Contributor_Address,Contributor_City,Contributor_Province,Contributor_Postal_Code,Aggregate_Contribution_Amount

Observed data: every row has Party_ID 8, Contributor_Type I (ALL) or P (S2P2), address "123 Main St", Toronto, ON, M5V 2T6.

Reads seeded data in periods 9503 and 9504 only; the only mutation anywhere in this plan is appending entity reports to spaces 9503 PARTY, 9503 CA riding 121, and 9504 PARTY. Do not use the 2025 Annual PARTY space (Security section generates there).

## Test Scenarios

### 1. Reporting (rows 66-69)

**Seed:** `apps/tax-receipts/e2e/tests/seed.spec.ts`

#### 1.1. Row 66: privileged user lists, generates, and downloads reports

**File:** `tests/eo/reporting/row-66-privileged-access.spec.ts`

**Steps:**
  1. Mutates: appends one ALL entity report to space 9503 PARTY. Sign in as sysadmin (it holds Generate entity reports and Read all records) and open /spaces/9503/PARTY/entity-reports.
    - expect: Heading 'Entity reports' and text 'Period 9503 · Party (province-wide)' are visible
    - expect: The 'Generate a report' form is shown with no permission warning
    - expect: The 'Generate' button is disabled while the reason is empty
  2. Fill 'Reason for generating (required)' with 'E2E row 66 <suffix>' (leave Report as ALL and the label as 'Green Party of Ontario'), confirm Generate is enabled, then click it.
    - expect: A new first row appears in the table with Kind 'ALL' and Rows '9'
    - expect: The row has a 'Download CSV' link and a 'Mark sent' button
  3. Click 'Download CSV' on that row and capture the download.
    - expect: The download succeeds, filename matches /^ALL-period9503-.*\.csv$/
    - expect: The first line equals the ALL header listed in the overview
  4. In a fresh context sign in as cfo (party CFO, holds View entity reports) and open the same URL.
    - expect: The table lists reports for the space, including a report generated by this scenario (match by Generated time) with a working 'Download CSV' link (page.request.get of its href returns 200 with content-type text/csv)

#### 1.2. Row 66: readonly and admin are refused the list, the CSV, and Generate

**File:** `tests/eo/reporting/row-66-unprivileged-refused.spec.ts`

**Steps:**
  1. Mutates: nothing. Precondition: obtain a report id by first signing in as sysadmin, opening /spaces/9503/PARTY/entity-reports, and reading the href of the first 'Download CSV' link (generate an ALL report with reason 'E2E row 66 seed <suffix>' if none is listed). Then clear cookies and sign in as readonly.
    - expect: Sign-in succeeds
  2. Open /spaces/9503/PARTY/entity-reports as readonly.
    - expect: Heading 'Entity reports' and the 'Generate a report' form render
    - expect: Text 'Only the party CFO, a designate, bookkeeper, or filer may generate reports.' is visible
    - expect: Text 'Your role cannot view generated reports.' is visible
    - expect: No table, no 'Download CSV' link, no 'Mark sent' button is present
  3. Fill 'Reason for generating (required)' with 'should not be allowed' and check the Generate button.
    - expect: The 'Generate' button stays disabled; do NOT click it
  4. Using page.request.get, request the CSV URL /api/entity-reports/<id>/csv captured above (on the web origin http://localhost:5174, session cookie shared).
    - expect: Status is 403 and the body is {"error":"not permitted to view entity reports"}
  5. Clear cookies, sign in as admin (Receipt administrator), and repeat the page checks, the disabled Generate check, and the direct CSV request.
    - expect: Same results as readonly: the warning and 'Your role cannot view generated reports.' show, Generate is disabled, CSV request returns 403
  6. Clear cookies and request the same CSV URL with no session.
    - expect: Status is 401 (or 403); the CSV body is never returned
